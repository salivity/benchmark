GPU vs Display Scaling: Latency Impacts in Benchmarking

This article explores the differences between GPU scaling and display scaling, focusing on how each method affects system latency during computer hardware benchmarks. You will learn the mechanics of both scaling techniques, their actual millisecond impact on modern components, and how to configure your test bench to ensure accurate, consistent, and repeatable benchmarking results.

The Mechanics of Scaling

Scaling is required when the resolution rendered by a game or benchmark does not match the native physical resolution of the monitor. For example, running a 1080p benchmark on a 4K monitor requires the image to be stretched to fill the screen. There are two ways to handle this:

  • Display Scaling: The GPU sends the raw, unscaled 1080p signal through the display cable. The monitor’s internal scaler chip intercepts the signal, resizes the image to 4K, and displays it on the panel.
  • GPU Scaling: The GPU renders the image at 1080p, uses its own hardware to upscale the image to 4K, and sends a native 4K signal to the monitor. The monitor's internal scaler is bypassed entirely.

How Display Scaling Affects Latency

Display scaling offloads the resizing workload from the graphics card to the monitor. In the past, this was the preferred method for low latency, as older GPUs had to use their rendering cores to scale images.

However, display scaling latency depends entirely on the quality of the monitor's internal scaler chip:

  • Low-End/Older Monitors: Many standard monitors use cheap scaler chips that must buffer an entire frame in the monitor's memory before resizing it. At 60Hz, a single frame buffer adds 16.67 milliseconds of input latency.
  • High-End Gaming Monitors: Modern gaming monitors utilize fast, dedicated scalers that process the image line-by-line rather than buffering the whole frame. This results in near-zero scaling latency, often adding less than 1 millisecond to the total signal path.

How GPU Scaling Affects Latency

A common misconception is that GPU scaling reduces framerates and increases render latency by stealing resources from the graphics card. On modern hardware from NVIDIA, AMD, and Intel, this is false.

Modern GPUs feature a dedicated hardware block called the Display Engine, which is completely separate from the shader cores used for rendering games.

  • Processing Latency: Because the rendered frame is already sitting in the GPU’s VRAM, the Display Engine scales the image as it is being scanned out to the display cable. This process happens in microseconds, adding virtually zero measurable latency to the system.
  • Bandwidth Limitations: Because GPU scaling sends a native-resolution signal to the monitor, it requires more cable bandwidth. If you are benchmarking a high-refresh-rate scenario on an older cable standard, GPU scaling might force chroma subsampling (color compression) or limit your maximum refresh rate, which indirectly hurts latency.

The Impact on Hardware Benchmarking

When benchmarking computer hardware—especially when using tools like NVIDIA LDAT or OSRTT to measure "click-to-photon" (end-to-end) system latency—your scaling choice can skew your data.

1. Isolating CPU/GPU Performance

Benchmarking often requires testing at 1080p to create a CPU bottleneck, even if the test bench uses a 1440p or 4K monitor. Because modern GPU Display Engines handle scaling independently of the rendering pipeline, turning on GPU scaling will not lower your average FPS or 1% lows. Both scaling methods yield identical framerate metrics on modern architectures.

2. Consistency Across Test Benches

If you are benchmarking latency across multiple systems connected to different monitors, Display Scaling introduces a variable. One monitor might add 0.5ms of scaling lag, while another adds 12ms. By forcing GPU Scaling, you bypass the monitors' internal scalers, ensuring that the scaling workload is handled solely by the hardware you are actually testing.

3. Signal Handshake and Mode Switching

During automated benchmarking runs that switch resolutions, Display Scaling forces the monitor to change its active signal mode. This causes the screen to go black for a few seconds and can occasionally cause benchmark software to crash or record massive latency spikes during the transition. GPU scaling keeps the monitor locked at its native resolution and refresh rate, resulting in instant resolution changes and cleaner benchmark data.

Best Practices for Benchmarking

To ensure your hardware benchmarks are accurate and free from scaling-induced latency anomalies, follow these rules:

  1. Run Native Resolution Whenever Possible: The best way to eliminate scaling latency is to avoid scaling altogether. Match your benchmark resolution to your monitor's native resolution.
  2. Use GPU Scaling for Multi-System Latency Tests: When testing at non-native resolutions (like 720p or 1080p on a 4K panel) to measure system latency, enable GPU scaling. This standardizes the signal output and removes the monitor's scaler chip as a variable.
  3. Use Display Scaling Only on Verified Monitors: If you are testing legacy GPUs (pre-2015) that lack modern dedicated display engines, or if you are hitting cable bandwidth limits, use Display Scaling—provided you are using a high-end gaming monitor known to have a zero-frame-buffer scaler.
  4. Document Your State: Always note whether GPU or Display scaling was used in your benchmark methodology, as click-to-photon latency numbers cannot be accurately compared if the scaling methods differ.
