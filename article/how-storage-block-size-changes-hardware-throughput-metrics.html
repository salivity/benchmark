How Storage Block Size Changes Hardware Throughput Metrics

This article explores how changing storage block sizes—specifically 4K, 64K, and 1M—drastically alters throughput metrics during computer hardware benchmarking. You will learn the mathematical relationship between block size and data transfer rates, how different block sizes stress distinct components of a storage drive, and why small blocks measure transactional speed while large blocks measure maximum bandwidth.

The Core Formula

To understand how block size affects benchmarking, you must first understand the relationship between Input/Output Operations Per Second (IOPS) and throughput (measured in MB/s or GB/s). The formula is straightforward:

Throughput = IOPS × Block Size

When you change the block size in a benchmark, you shift the workload between processing many small transactions and moving massive, continuous streams of data. Because of this, a storage drive will show wildly different throughput numbers depending on the block size selected.

4K Block Size: Testing Latency and IOPS

A 4 Kilobyte (4K) block size is the standard for measuring random read and write performance, as it matches the default page size of most modern operating systems.

  • Throughput Impact: Throughput in MB/s will look relatively low.
  • IOPS Impact: IOPS will be at their highest.
  • Hardware Bottleneck: The storage controller, firmware, and system CPU.
  • Real-World Equivalent: Booting an operating system, running databases, and loading background application files.

At 4K, every tiny piece of data requires its own command, address lookup, and completion signal. Because the drive spends most of its time managing this high transactional overhead, it cannot reach its maximum data transfer speed. For example, a fast SSD achieving 100,000 IOPS at a 4K block size will only generate about 409 MB/s of throughput.

64K Block Size: The Balanced Transition

Moving to a 64 Kilobyte (64K) block size shifts the benchmark from testing pure transactional overhead to testing data movement efficiency.

  • Throughput Impact: Throughput increases significantly compared to 4K.
  • IOPS Impact: IOPS drop noticeably as the drive takes longer to transfer each individual block.
  • Hardware Bottleneck: Internal drive parallelism and DRAM cache buffers.
  • Real-World Equivalent: Loading game assets, editing high-resolution photos, and moderate file transfers.

At 64K, the benchmark packs 16 times more data into a single I/O request than it does at 4K. This reduces the strain on the storage controller. Instead of getting bogged down by command processing, the drive can focus on pushing data simultaneously across multiple internal NAND flash channels (on an SSD) or reading continuous sectors (on a hard drive).

1M Block Size: Maximizing Bandwidth

A 1 Megabyte (1M) block size is used to find the absolute physical speed limit of the storage interface and the storage media itself.

  • Throughput Impact: Throughput reaches its absolute peak, often matching the advertised speeds on the hardware box.
  • IOPS Impact: IOPS drop to a very low number.
  • Hardware Bottleneck: The physical interface (SATA, PCIe 4.0, PCIe 5.0) and the raw write/read speed of the memory chips or magnetic platters.
  • Real-World Equivalent: Moving large video files, creating full system backups, and streaming uncompressed media.

With 1M blocks, command overhead is virtually eliminated. The storage controller receives a single command and simply opens the floodgates to transfer a massive chunk of data. A high-end PCIe 4.0 NVMe SSD only needs to process about 7,000 IOPS at a 1M block size to completely saturate the motherboard's PCIe bus and deliver 7,000 MB/s (7 GB/s) of throughput.

Summary of the Hardware Shift

When you change the block size in a storage benchmark, you are changing which part of the hardware you are testing:

  1. 4K tests the brains: It measures how fast the drive's controller and the computer's CPU can process queues and locate data.
  2. 64K tests the architecture: It measures how well the drive transitions from heavy processing to sustained data delivery using its internal channels.
  3. 1M tests the pipes: It measures the raw bandwidth limit of the physical connection and the maximum speed of the storage media.
