Benchmarking Server Security Hardware with Phoronix OpenSSL

This article explores the critical role of the Phoronix Test Suite, specifically the pts/openssl test profile and its broader cryptography suites, in benchmarking computer hardware for server security. It explains how these standardized tools measure a processor's capacity to handle intense encryption, decryption, and key generation workloads. By examining how these benchmarks test hardware acceleration, multi-core scaling, and algorithmic throughput, this guide clarifies how system architects evaluate and select server hardware capable of maintaining robust security without sacrificing network or application performance.

Understanding pts/openssl and the Cryptography Suite

The Phoronix Test Suite (PTS) is an automated, open-source benchmarking platform. Within this platform, the pts/openssl profile and the overarching pts/cryptography suite serve as industry standards for evaluating how computer hardware handles security-related workloads.

  • pts/openssl: This specific test profile utilizes the built-in benchmarking tool of the OpenSSL library (openssl speed). It stresses the CPU by executing continuous cryptographic operations and measuring the output in bytes per second or operations per second.
  • pts/cryptography: This is a collection of tests that includes OpenSSL alongside other cryptographic libraries and algorithms, such as Botan, Gcrypt, Blake2, Nettle, and Cryptsetup. It provides a holistic view of a server's cryptographic performance across different software implementations.

Evaluating Hardware Acceleration

Modern server processors do not rely solely on general-purpose computing cores to handle encryption. They include dedicated silicon and instruction sets designed to offload and accelerate cryptographic math. A primary role of Phoronix cryptography benchmarks is to verify the efficiency of these hardware-level features.

The benchmarks heavily test instruction sets such as:

  • Intel and AMD AES-NI (Advanced Encryption Standard New Instructions): Accelerates symmetric encryption used in bulk data transfer.
  • AVX-512 and VAES (Vector AES): Allows the CPU to process larger chunks of cryptographic data simultaneously.
  • ARMv8 Cryptographic Extensions: The equivalent acceleration hardware found in ARM-based server processors like AWS Graviton and Ampere Altra.

By running pts/openssl, hardware reviewers and systems engineers can immediately see the generational improvements in these instruction sets when comparing older server CPUs against newer releases.

Key Metrics for Server Workloads

Server security relies on different types of cryptography for different tasks. The Phoronix OpenSSL benchmark isolates these tasks to show exactly where a piece of hardware excels or bottlenecks.

Asymmetric Encryption (RSA)

When a client connects to a secure server via HTTPS, an SSL/TLS handshake occurs. This relies heavily on asymmetric algorithms like RSA. The pts/openssl benchmark measures RSA 4096-bit sign and verify operations per second. High performance in this metric indicates that a server CPU can handle thousands of new, simultaneous user connections without slowing down.

Symmetric Encryption (AES and ChaCha20)

Once a secure connection is established, the server uses symmetric encryption to transfer data rapidly. The benchmark tests algorithms like AES-128-GCM, AES-256-GCM, and ChaCha20-Poly1305. High throughput here ensures that the server can encrypt database traffic, VPN tunnels, and file transfers at line rate without maxing out CPU usage.

Hashing (SHA)

Data integrity and password verification rely on hashing algorithms. The benchmark measures throughput for SHA256 and SHA512. Strong performance here is vital for servers managing authentication databases, blockchain nodes, or secure file repositories.

Assessing Multi-Core Scaling and Efficiency

Servers rarely run single-threaded workloads. A critical role of the Phoronix suite is to execute these cryptographic tests across all available CPU cores and threads simultaneously.

Cryptographic workloads are "embarrassingly parallel," meaning they should scale linearly with the addition of more CPU cores. If a 64-core server does not achieve roughly double the OpenSSL score of a 32-core server from the same generation, the benchmark exposes underlying hardware bottlenecks. These bottlenecks usually involve thermal throttling, insufficient power delivery, or memory bandwidth limitations.

Furthermore, Phoronix can monitor CPU power consumption during the pts/openssl run, calculating performance-per-watt. For data centers, knowing how much electricity is required to encrypt a gigabyte of data is essential for managing operational costs.

Cross-Architecture Comparisons

The server market consists of competing architectures, primarily x86_64 (Intel Xeon and AMD EPYC) and ARM64. Because the Phoronix Test Suite compiles the exact same version of OpenSSL with the same compiler flags across different operating systems and CPU architectures, it provides an unbiased, apples-to-apples comparison.

System administrators use this data for hardware procurement. By reviewing Phoronix cryptography results, they can determine which specific CPU architecture delivers the highest TLS termination rates or VPN throughput for their budget, ensuring that security requirements do not degrade server responsiveness.
